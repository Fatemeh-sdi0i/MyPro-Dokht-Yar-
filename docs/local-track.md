# مسیر Local-first دوخت‌یار

این سند مسیر تکمیلی حالت محلی (Local-first) را توضیح می‌دهد. این مسیر فازهای قبلی (فاز ۱ تا ۷، PRهای #۲۹ تا #۳۱ و حالت سرور) را جایگزین نمی‌کند. آن‌ها به‌عنوان تاریخچه‌ی تکمیل‌شده باقی می‌مانند.

## هدف محصول

- هر مزون یک PWA شخصی روی گوشی یا کامپیوتر خودش دارد.
- داده‌ها روی همان دستگاه می‌مانند و بدون اینترنت کار می‌کنند.
- هیچ سرور، حساب کاربری، پیامک یا همگام‌سازی آنلاین در این مسیر نیست.
- پشتیبان JSON و پشتیبان رمزشده برای انتقال و نگهداری داده وجود دارد.
- حذف و بازگردانی برای مشتری، سفارش، همکار و تراکنش وجود دارد.
- حالت سرور و همگام‌سازی کد دست‌نخورده دارد و فعلاً غیرفعال است (`js/config.js`، `remote: false`).
- امکان توسعه‌ی چندکاربره در آینده حفظ شده است.

## ذخیره‌سازی در حالت محلی

| کلید | محل | محتوا |
|---|---|---|
| `dokhtyar.v3` | localStorage | کل داده‌ی مزون، رمزشده با AES-GCM (پاکت `{v, iv, ct}`) |
| `dokhtyar-vault` / `keys` | IndexedDB | کلید AES غیرقابل استخراج |
| `dokhtyar.backup.v3` | localStorage | نسخه‌ی رمزشده‌ی داده‌ی جایگزین‌شده در بازیابی (هرگز خودکار حذف نمی‌شود) |
| `dokhtyar.swap.v3` | localStorage | نسخه‌ی موقت برای جابه‌جایی؛ فقط برای برگشت |
| `dokhtyar.meta.v1` | localStorage | فقط زمان آخرین پشتیبان (`{"lastBackupAt": ms}`)؛ هیچ محتوای داده در آن نیست |

قواعد مهم:

- نوشتن کل داده در یک فراخوانی انجام می‌شود و بعد از آن بازخوانی و تأیید می‌شود. «ذخیره شد» فقط بعد از بازخوانی موفق نشان داده می‌شود.
- اگر مرورگر کلید را نگه ندارد، برنامه به حالت «فقط‌نشست» می‌رود. در این حالت هیچ متن ساده‌ای ذخیره نمی‌شود و هشدار نشان داده می‌شود.
- داده‌ی قدیمی `dokhtyar.v2` (ساده) فقط بعد از تأیید بازخوانی به نسخه‌ی رمزشده منتقل می‌شود.

## ماندگاری داده (F2)

- در راه‌اندازی حالت محلی، `navigator.storage.persist()` فراخوانی می‌شود. اگر مرورگر اجازه دهد، داده کمتر در معرض پاک‌شدن خودکار است.
- نتیجه در «تنظیمات › داده‌ها» یکی از سه پیام است: فعال، اجازه داده نشد، یا پشتیبانی نمی‌شود.
- این درخواست داده یا کلید را تغییر نمی‌دهد و خطای آن برنامه را متوقف نمی‌کند.

## یادآور پشتیبان (F3)

- بعد از دانلود موفق پشتیبان JSON یا رمزشده، زمان آن در `dokhtyar.meta.v1` ثبت می‌شود.
- اگر پشتیبانی گرفته نشده باشد، یا بیش از ۷ روز گذشته باشد، «تنظیمات › داده‌ها» هشدار می‌دهد.
- زمان نامعتبر یا آینده مثل «هرگز پشتیبان نگرفته» رفتار می‌شود.
- پاک‌شدن این کلید فقط یادآور را بازنشانی می‌کند و به داده آسیبی نمی‌زند.

## حذف و بازگردانی نرم (F4)

- در حالت محلی، رکورد حذف فیزیکی نمی‌شود. فیلد `deletedAt` تنظیم می‌شود و بازگردانی آن را پاک می‌کند.
- رکورد بدون `deletedAt` فعال است. پس داده‌ی قدیمی و پشتیبان‌های قبلی بدون مهاجرت کار می‌کنند.
- **مشتری حذف‌شده:** وقتی است که همه‌ی رکوردهای آن نام حذف‌شده باشند. در حالت محلی سفارش‌ها با نام مشتری به او وصل‌اند و شناسه ندارند.
- **سفارش مشتری حذف‌شده:** برچسب «مشتری حذف شده» می‌گیرد؛ وضعیت و حذف آن ممکن نیست.
- **بازگردانی مشتری:** سفارش‌هایش را خودکار برنمی‌گرداند. هر سفارش جدا بازگردانده می‌شود.
- **سفارش جدید:** برای نام مشتری حذف‌شده ثبت نمی‌شود.
- **فهرست‌ها و آمار:** شمارنده‌ها، داشبورد، سفارش‌های پیش‌رو، نمودار ماهانه و گزارش‌ها فقط رکوردهای فعال را حساب می‌کنند.

### محدودیت شناخته‌شده

اگر دو مشتری با نام یکسان داشته باشیم و یکی حذف شود، سفارش‌های آن نام باز می‌مانند تا وقتی مشتری فعالی با همان نام باشد. این محدودیت حالت محلی است. رفع کامل آن به شناسه‌ی پایدار برای مشتری و مهاجرت داده نیاز دارد و فعلاً لازم نیست.

## اجرای آزمون‌ها

از ریشه‌ی repo:

```bash
node --test --test-concurrency=1 tests/sync.test.js tests/jalali.test.js tests/local-store.test.js tests/backup-crypto.test.js tests/backup-validate.test.js tests/persistence.test.js tests/backup-reminder.test.js
```

از پوشه‌ی `tests/e2e` (به Playwright و Chromium نیاز دارد):

```bash
npm run test:local-undo        # F4: حذف و بازگردانی محلی
npm run test:persistence       # F2: ماندگاری داده
npm run test:reminder          # F3: یادآور پشتیبان
npm run test:local-encryption  # رمزنگاری حالت محلی
npm run test:backup            # پشتیبان رمزشده
npm run test:restore           # بازیابی محلی
```

آزمون‌های `e2e.test.js` و `import.e2e.test.js` به سرور زنده و `E2E_EMAIL` نیاز دارند و مربوط به حالت سرور هستند.

## تصمیم‌های ثبت‌شده

1. مسیر Local تکمیلی است؛ فازهای قبلی و تاریخچه‌ی PRها تغییر نمی‌کنند.
2. حالت سرور و همگام‌سازی کد دست‌نخورده دارد و بدون بررسی حذف نمی‌شود.
3. هیچ سرویس، حساب، هزینه یا انتقال داده‌ی واقعی در این مسیر لازم نیست.
4. حذف در حالت محلی نرم است و بازگردانی همیشه ممکن است.
5. تصمیم Safari (الف، ب یا ج) بعد از تست واقعی روی iPhone گرفته می‌شود.
