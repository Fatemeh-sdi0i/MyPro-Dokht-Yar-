# دوخت‌یار — نمونه اولیه‌ی رابط کاربری

رابط کاربری مدیریت مزون و خیاطی «دوخت‌یار». این نسخه یک برنامه‌ی **استاتیک (HTML/CSS/JS بدون وابستگی و بدون مرحله‌ی build)** است.

## وضعیت فعلی

| بخش | وضعیت |
|---|---|
| خانه، سفارش‌ها، مشتریان، همکاران، امور مالی، گزارش‌ها، تنظیمات | ✅ کامل در حالت محلی |
| ذخیره‌سازی پیش‌فرض | ✅ در localStorage همین مرورگر (فقط روی همین دستگاه) |
| PWA (نصب، کار آفلاین) | ✅ |
| فونت فارسی | ✅ داخل پروژه (Vazirmatn، بدون Google Fonts) |
| بک‌اند (Fastify + PostgreSQL) | ✅ کد و آزمون‌ها در `main`؛ در CI با PostgreSQL واقعی تست می‌شود |
| حالت سرور در رابط کاربری | ✅ کد آماده، اما **خاموش** (پرچم `remote` در `js/config.js`) |
| انتقال داده‌ی مرورگر به سرور | ✅ آماده (فقط برای مدیر، وقتی سرور خالی باشد) |
| ابزار استقرار، پشتیبان رمزنگاری‌شده | ✅ آماده، روی سرور واقعی اجرا نشده |
| سرور عمومی و دامنه | ⏳ منتظر تصمیم و بودجه؛ هیچ سرویس پولی خریداری نشده است |

**وضعیت فعلی پروژه:** نسخه‌ی عمومی همان نسخه‌ی استاتیک رایگان روی GitHub Pages است و داده‌ها روی هر دستگاه جداگانه ذخیره می‌شوند.

## اجرای محلی

راه اول — مستقیم:
۱. فایل `index.html` را در Chrome یا Edge باز کنید.

راه دوم — با سرور محلی (توصیه‌شده):
```bash
python3 -m http.server 8000
```
سپس `http://localhost:8000` را باز کنید.

## استقرار روی GitHub Pages

۱. این مخزن را در GitHub منتشر کنید (شاخه‌ی `main`).
۲. در **Settings → Pages** مقدار **Source** را روی **GitHub Actions** بگذارید.
۳. هر push به `main` از طریق `.github/workflows/pages.yml` به‌صورت خودکار منتشر می‌شود.

## ساختار پوشه‌ها

```
index.html        صفحه‌ی اصلی و ساختار تمام صفحات و مودال‌ها
css/styles.css    استایل‌ها (RTL، فونت وزیرمتن، واکنش‌گرا)
js/data.js        داده‌ی نمونه و توابع کمکی (اعداد فارسی، escape، شماره سفارش)
js/app.js         منطق رابط کاربری و رویدادها
sw.js             Service Worker (کش پوسته‌ی برنامه و کار آفلاین)
manifest.webmanifest  تنظیمات نصب PWA
icons/            آیکون‌های برنامه (SVG منبع + PNG)
.github/workflows/pages.yml   استقرار خودکار روی GitHub Pages
```

## تغییرات فاز ۱ نسبت به نمونه‌ی اولیه

- ساختار پوشه‌ها برای توسعه و استقرار (`css/`, `js/`, workflow)
- جلوگیری از تزریق HTML: تمام داده‌های وارد‌شده توسط کاربر هنگام نمایش escape می‌شوند
- شماره سفارش جدید بر اساس بیشترین شماره‌ی موجود ساخته می‌شود (قبلاً ممکن بود تکراری شود)
- نام ماه در «تحویل‌های نزدیک» از تاریخ واقعی گرفته می‌شود (قبلاً همیشه «آبان» بود)
- شمارنده‌ی «مشتریان کل» از داده‌ها محاسبه می‌شود (قبلاً عدد ثابت ۴۵ بود)
- فرم ثبت مشتری: اعتبارسنجی شماره‌ی موبایل ۱۱ رقمی
- بستن مودال با کلید Escape و پاک‌شدن فرم هنگام بستن
- اتصال رویدادها با delegation (بدون اتصال مجدد listener بعد از هر رندر)
- نوار پایین موبایل: همه‌ی ۷ بخش اکنون قابل دسترسی‌اند (قبلاً بخش‌های ۵ به بعد پنهان بودند)
- اصلاح یک قاعده‌ی CSS نامعتبر (`font: inherit`)

## PWA و کار آفلاین (فاز ۳)

- **نصب:** در Chrome/Edge روی دسکتاپ یا Android گزینه‌ی «نصب برنامه» را بزنید؛ در iOS از Safari گزینه‌ی «Add to Home Screen» (روی Safari واقعی آزمون نشده است).
- **کار آفلاین:** پوسته‌ی برنامه هنگام اولین بارگذاری ذخیره می‌شود. داده‌ها هم در همان مرورگر هستند، پس آفلاین هم قابل مشاهده و ویرایش‌اند.
- **به‌روزرسانی:** هنگام انتشار نسخه‌ی جدید، مقدار `VERSION` در `sw.js` را افزایش دهید (نسخه‌ی فعلی `v3.2.12`). کاربر پس از بارگذاری مجدد نسخه‌ی جدید را می‌بیند.
- فایل‌های `manifest.webmanifest`، `sw.js` و `icons/` مسیرهای نسبی دارند و زیرمسیر GitHub Pages را پشتیبانی می‌کنند.
- سرویس‌کار فقط روی `https` (یا `localhost`) فعال می‌شود؛ با باز کردن مستقیم `index.html` از فایل سیستم کار نمی‌کند.

## نقشه‌ی فازها

- **فاز ۱ (انجام‌شده):** مخزن قابل استقرار، رفع مشکلات رابط، GitHub Pages
- **فاز ۲ (انجام‌شده):** همکاران، امور مالی، گزارش‌ها، تنظیمات + ذخیره‌ی محلی (localStorage)
- **فاز ۳ (انجام‌شده):** PWA — manifest، Service Worker، آیکون‌ها، کار آفلاین
- **فاز ۴ (کد انجام‌شده، سرور منتظر تصمیم):** بک‌اند و API، پایگاه داده PostgreSQL، احراز هویت، انتقال داده، ابزار استقرار و پشتیبان. راه‌اندازی سرور و فعال‌سازی حالت سرور هنوز انجام نشده است.

## تغییرات فاز ۲

- داده‌ها در `localStorage` ذخیره می‌شوند؛ با بارگذاری مجدد حفظ می‌شوند. دکمه‌ی «بازگردانی داده‌های نمونه» در تنظیمات آن‌ها را پاک می‌کند.
- داشبورد و شمارنده‌ها از داده‌ها محاسبه می‌شوند (قبلاً عدد ثابت بودند).
- نام مدیر در تنظیمات، در نوار کناری و بالای صفحه هم نمایش داده می‌شود.
- پشتیبان JSON از همه‌ی داده‌ها دانلود می‌شود.
- پشتیبان رمزشده (اختیاری): فایل با گذرواژه و PBKDF2-SHA256 + AES-GCM دانلود می‌شود. گذرواژه فراموش‌شده قابل بازیابی نیست.
- بازگردانی از فایل (ساده یا رمزشده) در حالت محلی: فایل پیش از اعمال بررسی می‌شود؛ داده‌ی فعلی در پشتیبان محافظت‌شده (`dokhtyar.backup.v3`) نگه داشته می‌شود و هر بازگردانی ناموفق داده را تغییر نمی‌دهد. تا زمانی که پشتیبان محافظت‌شده وجود دارد، بازگردانی دوباره فعال نمی‌شود. فایل‌های حالت سرور در حالت محلی بازگردانی نمی‌شوند.
- تاریخ‌های فرم سفارش و تراکنش اعتبارسنجی تقویمی (شمسی) می‌شوند.
- حذف تراکنش نرم است: ردیف در «تراکنش‌های حذف‌شده» (بخش امور مالی) می‌ماند و با دکمه‌ی «بازگردانی» برمی‌گردد. جمع‌ها و گزارش‌ها ردیف‌های حذف‌شده را نمی‌شمارند.
- بازگردانی از فایل در حالت سرور (فقط مدیر): فایل کامل بررسی می‌شود؛ پیش از جایگزینی، نسخه‌ی داده‌ی فعلی سرور ذخیره می‌شود (قابل دانلود در تنظیمات) و جایگزینی در یک تراکنش انجام می‌شود. هر خطا داده را دست‌نخورده می‌گذارد.
- نمودار «عملکرد ماهانه» از سفارش‌های تحویل‌شده‌ی همان سال محاسبه می‌شود.

## محدودیت‌های شناخته‌شده

- در نسخه‌ی عمومی، داده‌ها فقط در همین مرورگر ذخیره می‌شوند و بین دستگاه‌ها همگام نیستند. پاک‌کردن داده‌های سایت در مرورگر، داده‌ها را از بین می‌برد.
- حالت سرور هنوز روشن نیست؛ تا زمانی که سرور راه‌اندازی و پرچم فعال شود، داده‌ها روی سرور ذخیره نمی‌شوند.
- بازگردانی سرور کل داده‌ی مزون را جایگزین می‌کند؛ نسخه‌های ذخیره‌شده پاک نمی‌شوند و رابط فقط ۲۰ مورد آخر را نشان می‌دهد.
- حذف مشتری، سفارش و همکار هنوز بازگردانی ندارد؛ فقط تراکنش‌ها بازگردانی دارند.
- اگر مرورگری نتواند کلید رمزنگاری را در IndexedDB نگه دارد، برنامه به حالت فقط‌نشست با هشدار می‌رود و هیچ داده‌ای روی دیسک نمی‌نویسد. در WebKit نسخه‌ی Playwright این حالت دیده شده؛ Safari واقعی هنوز آزمون نشده است.
- پشتیبان روزانه و انتقال آن به محل دوم هنوز زمان‌بندی نشده‌اند؛ به سرور نیاز دارند.
